# 月次コンテンツランキング Shorts 設計

## 1. 目的

ごうホームクリニック公式の YouTube、ブログ、Instagram について、前月に実際に読まれた・見られたコンテンツ TOP3 を毎月3本の縦型ショート動画として下書き生成する。

本機能は公開を自動化しない。データ取得、順位決定、台本作成、音声・字幕・映像のレンダリングまでを自動化し、人が数字、内容、発音、映像を確認した後に手動公開する。

## 2. 成果物

対象月ごとに以下の3本を生成する。

1. YouTube Shorts 前月再生回数 TOP3
2. 人気ブログ 前月ページビュー TOP3
3. Instagram 投稿 前月 views 増加 TOP3

各動画は 9:16、45〜60秒、短い TTS ナレーション、確定字幕、BGM付きとする。動画と同時に次の成果物を保存する。

- ランキング根拠を含む `ranking.json`
- 人が編集できるナレーション台本
- SNS投稿用タイトルと説明文
- 最終候補 MP4
- フレーム一覧の QA シート
- 音声・映像・順位確認結果

## 3. ランキング定義

### 3.1 共通

- 集計期間は Asia/Tokyo の前月1日 00:00:00 から末日 23:59:59 まで。
- 公開日の新旧にかかわらず、取得可能な過去コンテンツすべてを候補にする。
- 非公開、削除済み、権利上再利用できないコンテンツは除外する。
- 同値の場合は副指標、それも同値なら公開日時の新しい順で決める。
- 動画上では「累計」ではなく「YYYY年M月の実績」であることを明記する。

### 3.2 YouTube Shorts

- YouTube Analytics API の `creatorContentType=SHORTS` を使い、`video` 単位の `views` を取得する。
- 順位は前月中の `views` 降順。
- 同値の場合は前月中の `engagedViews`、公開日時の順。
- YouTube Data API の3分以内判定は表示用フォールバックとして残すが、月次ランキングの正本判定には使わない。

### 3.3 ブログ

- GA4 Data API で前月の `screenPageViews` を `pagePath` 単位に取得する。
- 対象は `^/20\d{2}/\d{2}/\d{2}/` に一致する本院サイトの記事URL。
- クエリ文字列を除去して同じ記事を集約する。
- 順位は前月中の `screenPageViews` 降順。
- 同値の場合は `totalUsers`、公開日時の順。

### 3.4 Instagram

- Instagram Graph API から投稿ごとの累積 `views`、`reach`、`saved`、`shares`、`total_interactions` を毎日保存する。
- 順位は月末スナップショットと前月末スナップショットの `views` 差分降順。
- 同値の場合は `total_interactions` 差分、公開日時の順。
- `reach` は参考値として保存するが、累積ユニークユーザーの差分は月内の再訪を表さないため順位には使わない。
- 投稿単位 Insights は期間指定した過去値を後から復元できない。厳密なランキングは、月初から翌月初までのスナップショットが揃った最初の月から開始する。
- スナップショットが不足する初回月だけは「前月公開投稿の現在 views TOP3」として別ラベルで生成できる。推定値を前月増加数として表示しない。

## 4. 既存処理との境界

`gohome-study-hub` はランキングデータの取得と正規化を担当する。既存の `src/data/portal.ts` が持つ以下の経路を再利用する。

- YouTube Data API のチャンネル・動画情報
- GAS Web App 経由の GA4 ブログランキング
- GAS Web App 経由の Instagram 投稿・Insights

月次処理では、ローリング180日や現在累計ではなく、明示した対象月の開始日・終了日を受け取る API を追加する。正規化後の共通マニフェストだけを動画側へ渡し、動画レンダラーから各サービス API を直接呼ばない。

`fal-seedance` はマニフェスト、画像、動画クリップ、音声から確定描画する。Seedance に日本語文字や順位数字を描かせない。今回のモーショングラフィックスは汎用後処理部品として実装し、既存求人アニメの標準表現にはしない。

## 5. データフロー

1. 対象月を `YYYY-MM` で指定する。
2. 3媒体の API から対象月データを取得する。
3. 媒体ごとのランキング定義で TOP3 を確定する。
4. API応答、取得日時、集計期間、指標を含む不変の `ranking.json` を保存する。
5. 各コンテンツのタイトル、画像、短い紹介文、動画クリップ候補を収集する。
6. ナレーション台本と確定字幕を生成する。
7. 過去の演出履歴から、今月使っていない演出候補を提案する。
8. 3本の仮動画をレンダリングする。
9. 自動QA後、人が確認する。
10. 合格した MP4 と投稿文だけを公開候補へ昇格する。

## 6. 共通マニフェスト

媒体ごとに次の形へ正規化する。

```json
{
  "schemaVersion": 1,
  "channel": "youtube",
  "period": {
    "timezone": "Asia/Tokyo",
    "startDate": "2026-06-01",
    "endDate": "2026-06-30"
  },
  "rankingMetric": "views",
  "rankingLabel": "6月の再生回数",
  "generatedAt": "2026-07-05T09:00:00+09:00",
  "items": [
    {
      "rank": 1,
      "contentId": "video-id",
      "title": "表示タイトル",
      "url": "https://example.com/content",
      "publishedAt": "2026-05-20",
      "metricValue": 1234,
      "secondaryMetricValue": 987,
      "thumbnailPath": "assets/rank-1.jpg",
      "clipPath": "assets/rank-1.mp4"
    }
  ]
}
```

外部URLは取得時の参照情報として残すが、レンダリング時はローカルへ固定保存した素材だけを使う。Instagram の一時的な CDN URL を最終成果物の依存先にしない。

## 7. 動画構成

標準尺は約54秒とする。

- 0〜3秒: 冒頭フック
- 3〜15秒: 第3位
- 15〜29秒: 第2位
- 29〜46秒: 第1位
- 46〜54秒: TOP3一覧と誘導

表示する数字は順位と対象月の実績値に限定する。過度な評価語や医療効果を示す表現を自動生成しない。ブログとInstagramは本文を丸ごと読み上げず、タイトルと事実ベースの一文だけにする。

## 8. 演出ライブラリ

「入れる場所」と「動き」を別々に指定する。

### 8.1 入れる場所

- `hook`: 冒頭フック専用
- `chapter`: 順位切り替え
- `none`: 特殊トランジションなし

### 8.2 初期モーション

- `cutout-zoom`: 文字の中に次の映像を表示し、文字を拡大して全面映像へ移行
- `split-reveal`: 背景が上下に開き、次の映像を表示
- `letter-scatter`: 文字が一文字ずつ散開して次の映像を表示

### 8.3 マンネリ防止

- 特殊トランジションは1本につき最大2回。
- 同じ媒体で前月と同じ `placement + motion` の組み合わせを第一候補にしない。
- 直近6か月の使用履歴を保存する。
- 背景画像、見出し、配色、速度を対象コンテンツに合わせて変える。
- Codexが候補と理由を提示し、制作時に最終指定する。完全自動決定にはしない。

## 9. 素材取得

- YouTube: 元の制作ファイルを最優先し、見つからない場合のみ公式チャンネル上の公開動画を取得する。
- ブログ: 記事のOG画像またはアイキャッチ画像をローカル保存する。利用できない場合はクリニック共通背景を使う。
- Instagram: 画像・Reelサムネイル・許可された短いReel区間を取得時にローカル保存する。
- 素材が横型の場合は、顔や重要テキストを切らない9:16レイアウトへ収める。無理なクロップはせず、背景ぼかしまたはカードレイアウトを使う。

## 10. 音声と字幕

- TTS入力は自然な漢字かな交じり文にする。
- 字幕は承認済み台本と一字単位で一致させ、意味単位で改行する。
- BGMは3本のシリーズ感を保つが、媒体ごとに軽い音色差を持たせる。
- 順位、タイトル、実績値の読み間違いを自動検査し、最終的には人が聴く。

## 11. 実行方式

### Phase 1: 初回検証

- 対象月を指定して手動実行する。
- 3媒体の `ranking.json` と仮動画3本を生成する。
- 数字、台本、演出、尺を人が確認する。
- Instagramの差分スナップショットがない場合は、初回限定ラベルを使用する。部分月の値を完全な前月値として扱わない。

### Phase 2: 月次下書き生成

- 指標の反映遅延を避けるため、毎月5日 09:00 JST に前月分を生成する。
- 自動処理は公開候補ディレクトリへの下書き作成まで。
- YouTubeへの投稿、公開日時設定、外部通知は人の承認後に行う。

## 12. エラー処理

- 3媒体は独立して処理し、1媒体の失敗で他の下書きを失わない。
- API認証失敗、期間不一致、TOP3不足、素材取得失敗は、その媒体を公開候補へ昇格させない。
- 前月値が取得できないときに累計値へ黙ってフォールバックしない。
- `ranking.json` の期間、指標、件数が不正ならレンダリングを開始しない。
- 一時ファイルと最終候補を分離し、途中失敗で前月の成果物を上書きしない。
- 失敗時は媒体、段階、原因、再実行コマンドを記録する。

## 13. QAと受入条件

### データ

- 対象月の開始日、終了日、タイムゾーンが一致する。
- TOP3が元API応答と一致する。
- 動画上の順位、タイトル、数字が `ranking.json` と一致する。
- Instagram初回フォールバックの表示が「前月増加」と誤認されない。
- Instagramの `views` 差分が2つの保存済みスナップショットと一致する。

### 映像

- 1080x1920 または 720x1280、H.264/AAC、全編デコード可能。
- 文字が安全域内にあり、重なり、欠け、擬似文字がない。
- 元映像の人物、記事画像、Instagram素材が不自然に切れていない。
- 同じ特殊演出を1本の中で過剰反復しない。

### 音声

- ナレーションと字幕が一致する。
- 順位、固有名詞、数字の発音を人が確認する。
- BGMがナレーションを隠さず、章間で不自然に途切れない。

### 公開前

- 人が3本を全編視聴する。
- 承認対象の SHA-256 を記録する。
- 承認後に内容を変更した場合は新しい候補として再確認する。

## 14. 対象外

- YouTube、Instagramへの完全自動投稿
- 3媒体の異なる指標を混ぜた総合ランキング
- AIによる医療効果・優劣の評価
- 外部アカウントのコンテンツ再利用
- 既存求人アニメ全編への文字くり抜き表現の強制適用

## 15. 初回成功条件

- 指定した1か月について3媒体のランキング根拠が保存される。
- 少なくとも YouTube とブログは厳密な前月値でTOP3が出る。
- Instagramは完全な月次スナップショットがあれば `views` の厳密差分、なければ明示された初回限定ランキングになる。
- 3本の下書きMP4、台本、投稿文、QAシートが生成される。
- 人の確認前にはどの動画も公開されない。
